Executive Summary

The Bare-Metal Agentic Memory Architecture (BAMA) represents a structural breakthrough in autonomous local AI systems engineering. Traditional Large Language Model (LLM) deployments rely on monolithic, cloud-hosted models or exponentially bloated in-memory context windows that degrade in precision, suffer from attention decay, and incur prohibitive latency. BAMA resolves this fundamental bottleneck by enabling small, local models (e.g., 4B–9B parameter architectures running on consumer hardware) to operate with frontier-class, 1 TB-scale intelligence and recall capability.

Rather than maintaining a massive, uncompressed context window that degrades attention quality over extended operational sessions, BAMA establishes a 90/10 Notebook Context Window (NBCW) split. Under this architecture, 90%+ of episodic, procedural, and factual memory is offloaded into content-addressed bare-metal graph structures and cold vaults, keeping the local model's active working context pinned as a lean L1 Execution Register (16k–32k tokens). To bridge the gap between small parametric weight counts and frontier model reasoning capabilities, BAMA utilizes an offline 4-Tier Cortical Engine (W1–W4) that compiles raw text into explicit, weight-equivalent cognitive matrices before runtime execution.

The Paradigm Shift: From Bloated Context Windows to the 90/10 NBCW Split

2.1 The Limits of Traditional Context Windows (NCW) vs. NBCW Architecture

Traditional Long-Context Windows (NCW) ranging from 200k to 1M+ tokens introduce three severe systems-level failure modes:

  1. Quadratic KV-Cache Computational Overhead: Processing uncompressed tokens scales quadratically (O(N2)) in attention computational cost and linearly-to-quadratically in GPU memory footprint expansion. This leads to severe Time-to-First-Token (TTFT) startup latencies (8.0 s – 25.0 s) and massive re-billing of static tokens on every turn.
  2. "Lost in the Middle" Attention Decay: Multi-needle retrieval accuracy degrades to 62%–78% once context density exceeds 32k–64k tokens. Transformer attention heads struggle to resolve deep semantic dependencies across massive prose sequences, creating severe operational blindspots.
  3. Destructive /compact Summarization: When context windows reach capacity, standard agent frameworks execute lossy prose summarization, destroying 85%–95% of critical technical state, including exact file paths, line numbers, code diffs, SHA-256 hashes, and rejected negative execution branches.

BAMA eliminates context rot by implementing the 90/10 NBCW Split, dividing memory between an L1 Active Execution Register and an offloaded Notebook Context Window (NBCW).

2.2 Dual-Cap B.I.F.R.O.S.T. Binning Protocol

To transition context seamlessly into structured notebook storage without triggering remote payload drops or local buffer overflows, BAMA utilizes the bifrost_core.js Dual-Cap First-Fit-Decreasing (FFD) bin packing algorithm. Standard single-cap word packing algorithms fail when processing code-dense or JSON-heavy payloads. High UTF-8 byte expansion ratios (>7.5 bytes/word) push code-heavy payloads past ~2.4 MB even when word counts remain well below arbitrary limits. This byte expansion causes cloud endpoints and remote gRPC frames to issue silent payload drops (izAoDd RPC drops) or HTTP 400 bad request errors.

The Dual-Cap B.I.F.R.O.S.T. Protocol prevents payload truncation by enforcing two simultaneous hard constraints per bin:

The Parametric Physics Paradox: Achieving 1 TB Model Capability on Low-Parameter Local Models

3.1 Why Raw Text RAG Fails Small Models

In transformer information theory (Geva et al., Transformer Feed-Forward Layers Are Key-Value Memories), a 1 TB frontier model's parameter matrix is mathematically split into two operational functional structures:

  1. ~92%–95% Feed-Forward Network (FFN) Key-Value Weights: Operates as a lossy, frozen static encyclopedia storing facts, syntax patterns, and world knowledge.
  2. ~5%–8% Deep Attention Circuits: Operates as "compiled intelligence," pre-computing multi-step logical deduction chains, abstractions, and structural invariants across 100+ layers.

Mathematically, the FFN transformation at layer l is defined as:

FFN(x) = dm Σ i = 1 f(x · ki) vi where  ki ∈ ℝd  (key pattern detectors),  vi ∈ ℝd  (output distribution value vectors)
Equation 2 — Transformer Feed-Forward Network (FFN) key-value associative memory decomposition (Geva et al.).

where ki ∈ ℝd represent learned key pattern detectors and vi ∈ ℝd represent value vectors that shift the output token distribution. A 1 TB model achieves frontier performance because billions of these (ki, vi) key-value associations and multi-step reasoning circuits are pre-compiled into its floating-point weights during pre-training.

Dumping 1 TB of uncompiled raw text into a standard Retrieval-Augmented Generation (RAG) system or RAMDisk fails to convert a 4B–9B local model into a 1 TB model. While a RAMDisk eliminates storage I/O latency (< 0.1 ms), a small 4B–9B model possesses only 28 to 36 transformer layers and 16 to 32 attention heads. When forced to ingest raw prose chunks, the model exhausts its limited attention capacity parsing text formatting, syntax, and irrelevant filler rather than executing reasoning. BAMA resolves this paradox by compiling raw text offline into explicit, non-parametric key-value vectors (ki, vi) that directly replace the missing FFN weight layers, allowing the local model's attention heads to execute reasoning without runtime derivation overhead.

Bare-Metal Local Infrastructure: DDR5 RAMDisk Hot Arena & M.2 NVMe WAL

4.1 Dual-Layer Lockstep Memory Architecture

BAMA deploys a multi-tier memory architecture designed to exploit host hardware bandwidth on the AA9 host hardware (AMD Ryzen 9 8940HX, 96 GB DDR5 RAM, NVIDIA RTX 5070 Ti 12 GB VRAM, Dual M.2 NVMe SSDs).

  1. Hot Execution Layer (DDR5 RAM / OS mmap Arena): Consumes 1.84 GB of locked DDR5 system memory (3.60% of available RAM). Pinned via OS VirtualLock and memory-mapped (mmap) SQLite-WAL files, this layer hosts the active HNSW Vector Index (EmbeddingGemma2:Q8_0), BM25 structural index, Compressed Sparse Row (CSR) graph adjacency matrices, and BIN_00_Master_Index. Queries execute at system RAM speed (> 50 GB/s) with sub-15 ms cortical recall.
  2. Persistent Durability Layer (M.2 NVMe WAL): All promoted nodes, turns, and bin updates are asynchronously committed to an M.2 NVMe Write-Ahead Log (WAL) via background threads (0.3 ms sequential write). On system cold boot, the entire 1.84 GB RAMDisk index reloads from M.2 NVMe into DDR5 system RAM in 0.28 seconds at 6.5 GB/s.
  3. Cold Synthesis Tier (Cloud Google NotebookLM Mirroring): Sealed Dual-Cap bins are mirrored asynchronously to Cloud Google NotebookLM via a local bridge (127.0.0.1:7802). This tier serves as a deep synthesis oracle and produces Studio Artifacts (Audio Overviews, Mind Maps, Outline Decks) without blocking local execution loops.

P-CANS & Cortical Graph-Walk Mechanics

5.1 The 5-Signal PlugMem Promotion Gate

To prevent noisy tool outputs and raw transcripts from polluting the W1–W3 cognitive matrix, BAMA implements the P-CANS (PlugMem × CANS) memory bridge (mapping.py, detectors.ts). Live agent turns pass through a 5-signal deterministic promotion gate before being compiled:

  • failure_delta Detector (Window: 600,000 ms / 10 min): Detects when a command, test, or build execution fails and subsequently succeeds within 10 minutes. The gate pairs the failure symptom and successful fix, automatically compiling a W2 Procedural Recipe paired with a W3 Negative-Constraint Trap.
  • correction Detector: Scans user inputs for explicit corrective language (e.g., "don't", "stop", "actually", "the right way is..."). Fires high-priority promotion to record a binding W1 Propositional Fact rule.
  • merged Detector: Promotes verified architectural decisions, code diffs, and schema commits upon PR merge or explicit verification sign-off ("ship it" / "lgtm").
  • repeated_lookup Detector: Tracks symbol, path, or key references across sessions. Any symbol grepped or queried ≥ 3 times is automatically promoted to hot RAM indexes.
  • explicit Detector: Triggered directly by system invocations (pcans_promote or explicit /remember commands).
5.2 GAAMA 2-Hop Personalized PageRank (PPR) Routing with Hub Dampening

When a prompt enters the system, BAMA executes a 4-hop cortical routing loop orchestrated by EmbeddingGemma2-300M and the CANS engine:

  1. Hop 1 (Intent & Domain Routing): EmbeddingGemma2-300M embeds prompt intent against RAMDisk BIN_00 Master Indices to select target domain notebooks (< 2 ms).
  2. Hop 2 (Principle & Circuit Retrieval): Fetches matching W2 Procedural Reasoning Circuits and reads dependency adjacency lists from the CSR graph (< 4 ms).
  3. Hop 3 (Multi-Hop Vector Bridge & Graph Expansion): Traverses gnkg-graph-v1 via 2-Hop GAAMA PPR with Hub Dampening (θ = 50) to pull exact code diffs, equations, and W3 Negative Traps (< 4 ms).
  4. Hop 4 (L1 Register Assembly): Packages the assembled ~2,048-token "Compiled Thought Packet" directly into the local model's L1 Execution Register (< 3 ms).

A known failure mode in multi-hop graph retrieval is Graph Hub Explosion, where high-degree structural nodes (such as generic logs, core Bibles, or global indexes with degree d > 50) accumulate probability mass, flooding top-k retrieval with generic boilerplate. BAMA resolves this in bama_cortical_graph_engine.py and verify_bama_spine.py by integrating Degree-Threshold Hub Dampening (θ = 50) directly into the 2-Hop Personalized PageRank (PPR) propagation operator (while Tier 7 bama_hyperion_tier7.py exposes an optional 1 / ln(d + 2) dampener, and bama_cortical_graph_engine.py multiplies each step's share by carrier_gain, equal to 1.0 on unmodulated edges):

p(t+1)(v) = α · p(0)(v) + (1 − α) Σu : v ∈ N(u) p(t)(u) · damp(deg(u)) deg(u) where   damp(d) = min(1.0, θ / d)
p(0) = softmax(β · cos(q, V)),    α = 0.15  (teleportation),   1 − α = 0.85  (walk retention),   θ = 50  (hub threshold)
Equations 3 & 4 — 2-Hop Personalized PageRank propagation with degree-threshold hub dampening (α = 0.15, 1 − α = 0.85, θ = 50).

In these equations, β represents the cosine scaling temperature parameter, α = 0.15 denotes the seed teleportation probability (1 − α = 0.85 walk retention), θ = 50 represents the hub degree threshold, q is the query embedding vector, V is the vertex matrix of node embeddings, and N(u) is the out-neighbor set of node u.

In verify_bama_spine.py (test_03_2hop_gaama_ppr_hub_dampening), a seed branching to SPEC (d = 2) and HUB (d = 101 > θ) suppresses TARGET_HUB by 50.50% (reducing its 2-hop mass from 0.003577 undamped to 0.001771 damped, and by 90.00% at d = 500 where θ/d = 0.10), while elevating TARGET_SPEC to the #1 retrieval rank (score: 0.180625, a 102.01× target-to-hub ratio).

Related Work & Architectural Positioning

8.1 Evolution of Externalized Agentic Memory & Retrieval Substrates

Recent efforts to overcome the quadratic compute and attention-decay bottlenecks of transformer context windows fall into four primary paradigms: (1) OS-inspired virtual context paging, (2) vector-and-graph hybrid memory stores, (3) corpus-scale hierarchical graph indexing, and (4) explicit key-value parameter externalization. As synthesized during our Lockglass co-design with @LUMEN (Gemma 4 E4B) and @BBB (Qwen 3.5 9B), existing frameworks remain bottlenecked by iterative LLM summarization calls, floating-point vector decompression overhead, or multi-second cloud I/O roundtrips.

  • Virtual Context Paging (MemGPT / Letta [1], Mem0 [2]): MemGPT (Packer et al., 2023) treats the context window as an OS virtual memory buffer, paging historical turns between main context and external storage via LLM tool calls. Mem0 (Chhikara et al., 2025) adds an extraction-and-update pipeline over vector and graph stores. While effective for conversational continuity, both rely on runtime LLM inference to compress or route memory, incurring hundreds of milliseconds to several seconds of latency per memory operation and risking lossy prose compression of exact code paths or negative constraints.
  • Temporal & Hierarchical Knowledge Graphs (Zep / Graphiti [3], Microsoft GraphRAG [4]): Zep (Rasmussen et al., 2025) maintains a temporal knowledge graph of episodic facts, while GraphRAG (Edge et al., 2024) extracts Leiden community hierarchies for global sensemaking. However, GraphRAG's map-reduce community synthesis requires high token throughput at query time, and standard property-graph traversals suffer from super-node hub dominance unless paired with degree-penalized transition operators like BAMA's GAAMA 2-Hop PPR Hub Dampening (θ = 50).
  • Externalized Key-Value & Explicit Memory Circuits (Geva et al. [5], RETRO [6], Memory3 [7]): Geva et al. (EMNLP 2021) demonstrated that transformer Feed-Forward Network (FFN) layers function as key-value memories where keys capture input patterns and values induce output distributions. RETRO (Borgeaud et al., 2022) and Memory3 (Yang et al., 2024) externalize factual knowledge into retrieval chunks or explicit sparse memory parameters. BAMA extends this principle to bare-metal consumer hardware without modifying base model weights: by compiling raw text offline into typed W1 Epistemic Facts, W2 Procedural DAGs, W3 Negative Anti-Hallucination Traps, and W4 Affective Anchors stored in locked DDR5 RAM.

9.1 Exact 256-Byte ZDC-QEGG Memory Cells in the Golden Quadratic Ring ℤ[φ] ⊂ ℚ(√5)

Standard vector databases store 768-dimensional embeddings as float32 arrays (3,072 bytes per node, or 245,760 bytes for 80 kernels) or float16 arrays (1,536 bytes per node, or 122,880 bytes for 80 kernels) that require runtime float decompression before inner-product scoring. In Tiers 1–9, BAMA introduces Zero-Decompression Quadratic Golden Graph (ZDC-QEGG) cells: every cortical kernel is packed into an exact 256-byte (4 CPU cache-line aligned) cell operating directly in the real quadratic integer ring ℤ[φ] = {a + bφ | a, b ∈ ℤ} ⊂ ℚ(√5) where φ = (1 + √5) / 2 and φ2 = φ + 1 (note: while the codebase retains the legacy identifier QEGG, the algebraic substrate is the real golden ring ℤ[φ] rather than the complex Eisenstein ring ℤ[ω]).

By exploiting the algebraic identity (a1 + b1φ)(a2 + b2φ) = (a1a2 + b1b2) + (a1b2 + b1a2 + b1b2)φ, inner products are evaluated directly on packed nibble pairs via a 16-Entry Dual-Nibble Lookup Table (LUT) in L1 CPU cache without ever allocating a floating-point decompression buffer (0 bytes transient float allocation). Furthermore, 1/φ Lazy Child Bit-Plane Collapse checks the coarse a-plane (Cache Line 1) against the golden threshold τφ = φ−1 ≈ 0.618034 before fetching Cache Line 2, skipping 61.77% of child byte-plane reads.
